# Aliax

Electron app that manages accounts across AI coding tools: switch which account each CLI/app uses, watch usage limits live, and show stats mined from local logs.

## Commands

- `bun run install-app` — build, install to `/Applications/Aliax.app`, pin to the Dock. This is the real app; dev is only for iterating.
- `bun run package` — build the bundle into `release/mac-arm64` without installing.
- `bun run dev` — run with hot reload. From a shell inside Claude Code, use `env -u ELECTRON_RUN_AS_NODE bun run dev` — that var is exported there and makes Electron boot as plain Node (`app` undefined).
- `bun run typecheck` — typecheck main/preload and renderer
- `bun run build` — production build to `out/`

## Architecture

electron-vite + React + TypeScript + Tailwind v4.

- `src/main/` — Electron main process. Owns everything that touches the filesystem and Keychain.
  - `adapters/` — one adapter per service. Today: a registry that detects installed tools. Next: per-service profile capture/activation and usage polling.
- `src/preload/` — context bridge; exposes `window.aliax`.
- `src/renderer/` — React UI. Never touches Node APIs; talks to main over IPC only.
- `src/shared/` — types used on both sides of the bridge.

## Where services keep credentials (macOS, verified on this machine)

- Claude Code: Keychain item `Claude Code-credentials`; state in `~/.claude` (stats: `~/.claude/projects/*.jsonl`, `stats-cache.json`)
- Codex: `~/.codex/auth.json`; history in `~/.codex/history.jsonl` + sqlite logs
- Cursor: Keychain items `cursor-access-token` / `cursor-refresh-token`; state in `~/.cursor`
- Gemini CLI: `~/.gemini`; Copilot: `~/.copilot`; opencode: `~/.config/opencode`; Amp: `~/.config/amp`; Continue: `~/.continue`; Factory: `~/.factory`

## Invariants that keep this trustworthy

These exist because each was violated once and produced a silent, confusing failure:

1. **Identity comes from credentials, never from a metadata file.** Tools rewrite their own account files from memory; a running session will happily stamp the wrong account on disk. `capture` relabels from `adapter.identify(blob)`, and `repairProfiles` fixes existing rows at startup.
2. **Never claim a switch worked without proving it.** `activate` re-reads live identity and fails loudly when it does not match.
3. **Never verify by searching storage bytes for an id.** Chromium-style storage keeps traces of every account that ever signed in, so substring matching lies.
4. **Never delete a user's saved session.** Skip and explain instead.
5. **Report no-ops.** If a target could not be changed, say which and why; a success toast over an unchanged system is the worst outcome.
6. **Adding an account never switches to it.** Sign-in only writes to the vault; the live account changes solely through an explicit switch. Where a tool's own login command mutates live credentials (`codex login`), snapshot them first and put them back afterwards.
7. **Surfaces link through profiles, not through each other.** Each capture files every surface under the account THAT surface is signed into — `capture` saves the CLI credentials under their account and `captureCompanion` saves the app session under its own (creating an app-only profile keyed by email if needed; its accountId upgrades to the credential uuid when CLI creds arrive). Switching restores whichever halves the target profile owns and names what stayed unchanged; recapture-before-switch re-files both surfaces so nothing signed in out-of-band is lost.
8. **Never show one indicator for two logins.** A row shows badges for each surface it owns (`CLI`, `App`), and a surface signed into an unsaved account raises a section notice. `Save current` files a mismatched desktop session under its own account's profile (invariant 7), never under the CLI account's.
9. **Only store a session the provider confirms is alive.** The Claude desktop app rotates its claude.ai session and flushes to disk only on quit, so cookies scraped from a running app are often already invalid (`account_session_invalid`). Verify via `claude.ai/api/bootstrap` — a null `account` means dead — and never save or install an unverified session. The reliable source of an app half is Aliax's own sign-in window, which receives a freshly minted session.
9b. **Claude sign-in stays in Aliax's own window — do not "just use the default browser".** It looks like an easy win (the system browser already has your Google/SSO session, and Claude Code's CLI does register `http://localhost:3118/callback` on the same OAuth client, so the loopback flow genuinely works). It was tried and reverted: the browser keeps the claude.ai cookies, and those are the ONLY reliable app half, because scraping the desktop app's on-disk session usually yields a dead key (invariant 9). The window's cookie jar is `persist:aliax-claude-login` and is never cleared, so the Google login is a ONE-TIME cost per install — later adds get Google's account chooser and still capture both halves. Wiping app data resets that, which is what makes the first-run friction look permanent.
10. **One service can span two independent logins** (Claude CLI OAuth vs. the desktop app's claude.ai web session). Treat them separately and name the account in every message.
11. **`codex login` revokes the grant sitting in auth.json before signing in** (logout-first; the binary ships `login/src/auth/revoke.rs`). Adding account B with account A's file in place kills A's saved login everywhere. Stash auth.json out of the CLI's sight for the duration of the login and restore it after.
12. **One rule for every host: only touch a session a scriptable terminal owns.** `terminalOwns` asks (read-only, before any kill) whether Terminal.app or iTerm2 owns the process's tty. Those are killed and resumed in their own tab; every other host — an editor's built-in terminal, a wrapper's background agent, tmux — is left running and reported. There are deliberately no per-application special cases and no new-window fallback: relocating someone's session is worse than leaving it on the old account and saying so. Aliax previously special-cased T3 Code by process name, which broke the moment the app shipped as "T3 Code (Nightly)".
13. **Sessions restart in the terminal they lived in.** Live sessions cannot adopt swapped credentials (they hold tokens in memory and write them back, invariant 1), so for an unproxied session in a scriptable terminal the kill is unavoidable — but the window survives it. `reopenSession` types the resume command into the tab owning the dead process's tty, and returns false rather than relocating anything.
14. **GUI-launched programs never read your shell.** An editor's embedded CLI session inherits the editor's environment, not `.zshrc`, so a shell snippet can never reach it. The only route is the CLIs' own config (`~/.claude/settings.json` `env` block, `~/.codex/config.toml` `chatgpt_base_url`) — which must name an endpoint that is valid even when Aliax is closed. Hence the shim (`resources/aliax-shim.mjs`, installed as the `com.aliax.shim` LaunchAgent): it owns a fixed port for good, forwards to Aliax's gateway when the marker names a live pid, and pipes straight to the provider otherwise. It holds no credentials, and `KeepAlive` revives it (launchd throttles that by ~10s). Never write CLI config until the helper answers. On removal, delete only the exact values Aliax wrote and keep the helper alive until every process that captured its URL has exited; changing config cannot change a running process's environment. Packaging must ship the script via `extraResources`.
15. **Instant switching (opt-in) routes CLI traffic through a localhost gateway** (`proxy.ts`) that replaces the Authorization header per request with the account pinned by the last switch, so running sessions follow a switch without restarting. Hard-won details: Chromium rejects reserved headers (`sec-*`, `accept-encoding`, …) with `ERR_INVALID_ARGUMENT`, so strip them; `net.fetch` returns decoded bytes, so drop the upstream `content-encoding`/`content-length`; `duplex` is invalid on a buffered body; and Codex needs path-aware upstreams (`/v1/*` → `/backend-api/codex`, everything else → `/backend-api`). Endpoint overrides are `ANTHROPIC_BASE_URL` (env) and `chatgpt_base_url` (Codex `-c` flag, so `config.toml` is never touched). Routing is guarded on a marker file naming a live pid, so a closed or crashed Aliax leaves both CLIs on their normal endpoints. Pin by profile, not by reading disk, or a CLI writing its own refreshed tokens back would drag proxied sessions to the old account.
16. **A stored credential snapshot is stale the moment the tool refreshes.** Claude's access token lives one hour and the CLI renews it in the Keychain, so a vault copy is dead within the hour. When the pinned account is the one the CLI holds, serve the LIVE credential and adopt it back into the vault; only a pinned account the CLI is *not* holding is ours to refresh. Getting this wrong makes the gateway send an expired token and then try to renew it with a superseded refresh token, which surfaces to the user as "OAuth revoked" on a perfectly healthy account. The same rule governs usage polling: Anthropic buckets rate limits PER TOKEN, so polling the active account with the vault snapshot can sit on 429 indefinitely while the CLI's own Keychain token answers 200 — `usage` polls the active account with the live credential and adopts it into the vault.
17. **Never change the Electron app name.** `safeStorage` derives its key from a Keychain item named `"<app name> Safe Storage"`, so renaming the app — via `app.setName`, or just by adding `productName` to package.json, which Electron reads in dev — silently switches to a different key and every previously stored secret fails to decrypt. It looks like corrupted credentials ("saved sign-in unreadable") but nothing is lost: the old Keychain item survives untouched, and reverting the name restores access. The name here is `aliax`; a packaged build sets its display name in `electron-builder.yml`, which does not affect the dev app. Dev-app cosmetics (Dock hover name, Dock icon) come from the dev bundle itself: `scripts/brand-dev-app.sh` (run on postinstall) sets `CFBundleDisplayName` and swaps `electron.icns` in `node_modules/electron/dist/Electron.app`, then re-signs ad hoc. It must never touch `CFBundleName` — that feeds the runtime app name that safeStorage keys the vault by. The menu-bar app title next to the Apple menu still says "Electron" in dev; only packaging fixes that. `usage()` also self-heals a decrypt failure on the ACTIVE account by recapturing live credentials, and never deletes the stored blob (invariant 4).
18. **A rotating refresh token has exactly one rightful holder.** OpenAI invalidates the previous refresh token on every refresh and treats reuse of a superseded one as theft, revoking the whole grant — access tokens included. So: watch `~/.codex/auth.json` and pull every rotation into the vault (`watchLiveCredentials`); never background-refresh the active account's copy (the CLI owns it); refresh stored copies only near access-token expiry (48h margin on a 10-day token); and on a 401 with an unexpired token, report "login revoked" instead of refreshing, because presenting the superseded token would kill any session still alive elsewhere.
19. **`/usage` can never reflect an instant switch, and settings.json beats the environment.** Two measured facts about Claude Code, both easy to get wrong. First: the CLI asks `api.anthropic.com` for `/api/oauth/usage` directly and does NOT send it through `ANTHROPIC_BASE_URL` — verified by pointing the CLI at a logging proxy and running `/usage`, which drew live percentages while the proxy recorded only `/v1/messages` and `/api/hello`. Instant switching works purely by swapping the Authorization header at our gateway, so it moves model traffic and cannot move `/usage`. Never treat `/usage` as evidence a switch did or did not land, and say so in the switch notes, because it reads as a dead feature. Second: an `env` block in `~/.claude/settings.json` OVERRIDES an exported `ANTHROPIC_BASE_URL` — so detecting proxied sessions from the process environment alone missed every GUI-launched session, which is the whole population instant switching exists for. `routedThroughAliax` checks the environment, then falls back to the settings file compared against the process start time (`ps -o lstart=`, whole seconds).
20. **Some sessions have no terminal at all.** An editor driving Claude through `@anthropic-ai/claude-agent-sdk` (T3 Code does) spawns the binary over pipes, so it has no controlling tty and never appears in `cliProcesses`. It cannot be restarted from outside its host — T3 Code ships no scripting interface, no `.sdef` — so `headlessCliProcesses` exists only to name them in the switch notes. Never kill from that list: there is no way to put the session back.

## Rules

- All provider HTTP calls in the main process MUST use Electron's `net.fetch`, never Node's global `fetch` — Cloudflare blocks Node's TLS fingerprint on chatgpt.com (and could on the others).
- **Never match the OAuth landing page by full URL.** Anthropic moved it from `console.anthropic.com` to `platform.claude.com` (the old host appears zero times in Claude Code 2.1.220), and a `startsWith(CLAUDE_REDIRECT)` test then silently stopped firing: the code arrived on screen and the window sat on "Waiting for sign-in" until the user closed it, which reported "sign-in cancelled". Match on `pathname` (`/oauth/code/callback`, `/oauth/code/success`) and keep `CLAUDE_REDIRECT` in step with what the CLI sends. Path matching is also what keeps Google's own SSO hops from false-positiving, since those URLs carry a `code` param too. A callback page with no code yet must keep waiting, not resolve null.
- Anthropic OAuth token exchange and refresh must hit `api.anthropic.com/v1/oauth/token`, never the `console.anthropic.com` mirror: console rate-limits non-CLI user agents for hours at a time and returns 429 on every call, while the api host answers normally.

- **Poll one account at a time, and lean on the cache.** Every profile in a service hits the same host, so firing them together earns a 429 that leaves the later accounts with no usage *and* no plan — which is what made three of four Claude rows look empty. `usage(serviceId, force)` walks profiles in sequence; a rate-limited answer with nothing to fall back on retries at half the TTL — never seconds, because fast retries keep the token's own rate-limit bucket saturated; and a report keeps the last known plan when the poll fails, since a plan changes about once a year. The Refresh button passes `force: true` to bypass the freshness cache and poll the APIs live; a forced refresh also blanks the usage state for each service first (`refreshUsage` deletes the keys) so the rows drop to skeleton bars and the reload is visible, then repopulates as each provider answers — the background 5-minute poll updates in place with no flash. But `force` NEVER bypasses an active rate-limit window (`report.rateLimit.until > now` short-circuits to the cached report first) — a manual refresh that hammered a 429 is the exact thing that once pinned an account for an hour. On a 429 the report keeps its last good windows and gains `rateLimit: { provider, until }`; the countdown comes from the `Retry-After` header (parsed by `retryAfterMs` in adapters/types.ts, seconds or HTTP-date) and the row shows an amber "Rate limited by X · Ym left" line under the account, bars intact. A later successful poll clears the flag. Clearing `userData/usage-cache.json` to force a cold fetch is not free — a handful of forced polls can rate-limit one account for hours.
- Secrets never touch disk in plaintext — profile credential sets go in the macOS Keychain; only metadata (names, timestamps) in app storage.
- Usage endpoints are unofficial and break; isolate every provider call inside its adapter.
- Account switching for GUI apps (Cursor app, Claude app) is fragile (Safe Storage) — deferred; CLI switching first.

## UI

shadcn primitives (`components/ui/`) + ReUI components (`components/reui/`: badge, alert, icon-tile) + BeUI motion (`components/motion/`: stateful button, tabs, loader, animated number), dark-only via tokens in `main.css`.

Layout: a drag-region title bar (wordmark, segmented tabs, refresh/settings/mini) over a scrolling body capped at `max-w-[62rem]`. One panel per service (`@utility panel` in `main.css`: raised sheet, lit top edge, two-layer shadow, near-invisible border). A panel header carries the brand tile, name and its two actions; rows are a flush divided list inside it, never nested cards.

Row grid is fixed so usage bars line up across every service: avatar, name (email on a second line only when a nickname hides it), a `21rem` two-slot usage block, then an `11.5rem` status column holding the `CLI`/`App` chips it already owns and the Switch button when it does not own the CLI. Empty slots stay reserved rather than collapsing.

Rules this UI holds to: one radius system (panels `rounded-xl`, controls `rounded-md`), one accent (near-white primary), no glow, no nested cards, no chip that repeats what a neighbouring line already says. Brand marks are Simple Icons paths vendored in `components/brand.tsx` so they draw offline. Motion is limited to four places that pay for themselves: the tab indicator, the row entrance stagger, the Switch button's idle-to-loading morph, and the usage percentages.

Window modes (normal 1280x900 / mini 372x460) are applied by the main process (`applyWindowMode`) and persisted in settings. The app icon lives in `build/` (`icon.png` + `icon.icns`, generated from the logo art over a dark rounded plate with a green glow); dev runs set it via `app.dock.setIcon` since only packaged builds read the bundle, and `app.setName('Aliax')` + `productName` cover the name. The icon is the only place the logo appears — the app chrome deliberately carries no logo or wordmark. Registries in `components.json`: `@reui` (needs `REUI_LICENSE_KEY` from `.env.local`; item URL is `/r/{style}/{name}.json`, style `radix-nova`; the registry rate-limits bursts of installs; it resolves the `components` alias to `src/` here, so move installed files into `src/renderer/src/` afterwards) and `@beui`. ReUI has no generic primitives (button etc. come from plain shadcn); `@reui/frame` installs with mangled utility classes, so it is not used. `dark:` is redefined as an always-on variant in `main.css` because registry components ship dark-mode utilities.

## Usage bar colours

Judged against the window's own clock, never a flat cutoff: 37% left is comfortable with a day to go and alarming with six days to go, so a level-only rule paints both the same (it painted Fable at 37% green). `onPaceLeft` is the share of the window still to come; health is `left / onPaceLeft` — 0.95+ good, 0.7+ warning, below that critical — with a hard critical floor at 10% left and a green pass once the window is nearly over. The tick on each bar marks that same on-pace point, so fill past the tick reads as ahead at a glance.

## Claude usage windows

The authoritative source is the response's `limits` array, NOT the top-level window keys. Per-model caps arrive there as `weekly_scoped` entries carrying `scope.model.display_name` (e.g. "Fable"), while the matching top-level keys (`seven_day_fable`, …) do not exist at all — reading only the keys left a model cap sitting at 63% invisible. `session` is the 5-hour window, `weekly_all` the overall weekly one. Keys remain a fallback for accounts the newer shape has not reached.

## Stats

`src/main/stats/`: an incremental indexer over the CLIs' own session logs into SQLite (`userData/stats.db`), and a query layer. Indexing is keyed by (mtime, size, byte offset) so a rescan of ~5,000 Codex rollout files costs nothing after the first pass.

The seam worth knowing: **Codex writes its rate-limit state into every session log**, which is months of burn history available immediately (224 days here) — Claude's logs carry per-message token usage but no limit state, so its curve only starts from Aliax's own polling. Claude also tags each message with `entrypoint`, which is how "usage by surface" can show that the SDK, not the CLI, is the real consumer.

Cycle boundaries are detected from a DROP in used percent, never from `resets_at`: these windows roll, so the reset time drifts with every sample and grouping by it invents thousands of one-sample "cycles" (it produced 3,927 where ~230 was right).

Charts are EvilCharts (`@evilcharts` registry, Recharts engine) in `components/evilcharts/`. Three of its traits bite: `layout` is INVERTED from Recharts (`layout="horizontal"` gives horizontal bars) and the axes derive their own type from it, so never pass `type`; `areaProps`/`lineProps` are declared but never applied, and stacking is chart-wide via `stackType="stacked"`, so a per-series stack is impossible; and the radial chart keys its config by each row's `nameKey` VALUE, not by the value key. The categorical palette in `lib/viz.ts` passes all six colour checks against the card surface — re-validate before substituting hues.

## Packaging

`electron-builder.yml` builds an ad-hoc-signed `Aliax.app` (arm64, `dir` target — no dmg, since this installs locally); `scripts/install-app.sh` quits any running copy, copies it to `/Applications`, re-signs it in place, re-registers it with LaunchServices and pins it to the Dock once. Apple Silicon refuses to launch a bundle with NO signature, so ad-hoc signing is mandatory, not optional.

Anything read from disk at runtime must ship via `extraResources`, never `files`: an asar path is not a real file, so `nativeImage` and the LaunchAgent cannot read from inside the archive. That covers `aliax-shim.mjs` and the tray icons — both resolve through `process.resourcesPath` when `app.isPackaged`.

The packaged app runs as `Aliax` while dev runs as `aliax`, which are different safeStorage keys (invariant 17). `vault.readSecret` therefore falls back to decrypting with the other names' Keychain keys — Chromium's own scheme: AES-128-CBC, PBKDF2-SHA1(password, "saltysalt", 1003), IV of 16 spaces, after the `v10` tag — and re-encrypts under the current name, so the two builds share one vault and a rename can never strand credentials again.

Testing the packaged app from a Claude Code shell needs `env -u ELECTRON_RUN_AS_NODE`, exactly like `bun run dev`; without it the binary boots as plain Node and exits 0 in silence.

## Updates

`bun run release [patch|minor|major]` bumps the version, builds signed + notarized zip/dmg, and publishes to the public feed repo `github.com/LandonDev/aliax-releases` (artifacts only; source stays local). The script preflights its three credentials — Developer ID Application cert in the Keychain, notary profile `aliax` (`xcrun notarytool store-credentials`), `gh` auth — and prints the exact fix when one is missing.

In the app, `src/main/updater.ts` checks the feed on launch and every 4 hours; the renderer shows one title-bar pill that walks available → downloading → restart (`quitAndInstall`, which runs the normal `before-quit` cleanup). Download starts only on click, never in the background unasked. Failed background checks stay silent; only a failed user-requested download surfaces.

Hard-learned constraints: the mac updater needs a `zip` target (dmg is only for first installs); `dir` builds get no `app-update.yml`, so `install-app.sh` writes one — but only when it could sign with a Developer ID, because Squirrel.Mac refuses to apply a Developer ID release over an ad-hoc-signed install. Release builds must be signed + notarized or every user's updater rejects them.

## Menu bar

`src/main/tray.ts` puts every saved account in the macOS menu bar: one line per account with a check mark on the active one and a click to switch. The usage bar is a REAL bar drawn into each item's `icon` (raw premultiplied BGRA at 2x via `nativeImage.createFromBitmap`) — block characters next to proportional menu text read as garbage. Colour comes from the shared pace-aware health in `src/shared/health.ts` (extracted so the menu and the window can never disagree), with the on-pace notch drawn in. Anything that changes accounts outside the window must `broadcast('accounts:changed')` (`events.ts`, wired to `webContents.send` — a callback hub, not an import, to avoid the index.ts cycle); the renderer subscribes and force-refreshes, otherwise a menu-bar switch sits invisible in the open window and reads as broken. A failed menu switch fires a native Notification, because a menu has no toast (invariant 5). The icon is `build/trayTemplate.png` (+`@2x`), pure black with the shape in alpha so macOS inverts it per theme. `createTray` takes the show-window callback as an argument — importing it from `index.ts` makes a cycle that leaves `createTray` undefined at call time. "Open at login" lives here and in Settings; both route through `setLaunchAtLogin`, which sets `openAsHidden` so a login start goes to the menu bar rather than stealing focus.

## Settings & switching

`userData/settings.json` holds `windowMode` and `switchTargets` (serviceId → targetId → enabled; default on). Each adapter declares `targets` (claude/codex: cli, desktop, t3; cursor: app) and its `activate` honors the enabled set. Profiles carry optional `nickname`/`color` (edited via `profiles:update`).

## How it works today

- Vault (`src/main/vault.ts`): profile metadata in `userData/profiles.json`; credential blobs encrypted with Electron safeStorage in `userData/secrets/`. Claude Desktop session state (Cookies, Local/Session Storage) rides along as a per-profile tar.
- Adapters (`src/main/adapters/`): `capture` reads live credentials into a blob, `activate` writes a blob back (quitting/relaunching the GUI app when needed), `liveAccountId` identifies the logged-in account cheaply (no Keychain), `usage` returns percent-used windows.
  - Claude Code: Keychain item + `~/.claude.json` oauthAccount + desktop session tar; usage from `api.anthropic.com/api/oauth/usage` (unofficial). The desktop app authenticates through a claude.ai web session (Cookies/Local Storage), entirely separate from the CLI's OAuth token, so the two can hold different accounts; `Save current` snapshots both together and switching restores the pair. Never verify a desktop archive by searching leveldb for an account uuid — that storage keeps traces of every account that ever signed in, so matching lies. Never delete a saved archive.
  - Codex: `auth.json`; identity from the id_token JWT; usage parsed from `rate_limits` snapshots in `~/.codex/sessions/*.jsonl` — active account only. Plan comes from the id_token too: OpenAI stamps `chatgpt_plan_type` and `chatgpt_subscription_active_until` (= next billing date on auto-renew) into the `https://api.openai.com/auth` claim, so no billing endpoint exists or is needed — decode the stored token, even expired, and the claims refresh with every token rotation.
  - Cursor: two Keychain items + `cursorAuth/*` keys in `state.vscdb` (via `node:sqlite`). Usage comes from the IDE's RPC backend, NOT the web API: `POST api2.cursor.sh/aiserver.v1.DashboardService/GetCurrentPeriodUsage` (plain-JSON ConnectRPC, `Authorization: Bearer <access token>`, body `{}`) returns `planUsage.autoPercentUsed`/`apiPercentUsed` — the exact meters the app's Plan & Usage screen draws — plus billing cycle bounds and the on-demand spend cap. The web `cursor.com/api/usage` is the retired request-quota shape and returns nulls on current plans (it once read as "no metered usage"); it remains only as a fallback for old-plan accounts. Plan tier from `cursor.com/api/auth/stripe` (cookie `WorkosCursorSessionToken=<sub>::<access>`); other `cursor.com/api/dashboard/*` POSTs exist but demand an `Origin: https://cursor.com` header. RPC method names live in plain sight in `/Applications/Cursor.app/Contents/Resources/app/out/vs/workbench/workbench.desktop.main.js`.
- In-app sign-in (`src/main/login.ts`): Claude via Claude Code's public OAuth client (PKCE, manual code paste); Cursor via its deep-link flow polling `api2.cursor.sh/auth/poll`; Codex by spawning `codex login`. New accounts save to the vault and activate immediately.
- Active profile = stored profile whose accountId matches the live one, so it stays truthful if the user switches outside Aliax. Before activating, the current live credentials re-capture into their matching profile so tool-refreshed tokens aren't lost.
